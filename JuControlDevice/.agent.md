# JuControlDevice Module - Development Guidelines

## Architecture Overview

This module has been refactored to follow modern PHP and software engineering best practices:

### Key Improvements Made:

1. **Separation of Concerns**: Split the monolithic class into focused, single-responsibility classes
2. **Dependency Injection**: Removed hard dependencies and introduced proper DI patterns
3. **Interface-Based Design**: Added contracts for better testability and flexibility
4. **Exception Handling**: Implemented proper exception hierarchy with meaningful error messages
5. **Configuration Management**: Centralized constants and configuration
6. **Modern PHP Features**: Utilizes PHP 8+ features like match expressions, constructor property promotion
7. **PSR Compliance**: Follows PSR-4 autoloading and PSR-12 coding standards

### Directory Structure:

```
src/
├── Contracts/          # Interfaces defining contracts
├── Devices/           # Device-specific implementations
├── Services/          # Business logic services
├── Config/            # Configuration and constants
└── Exceptions/        # Custom exception classes
```

### Key Classes:

- **JuControlDeviceModule**: Main module class (refactored from original)
- **DeviceInterface**: Contract for device implementations
- **ApiClient**: HTTP client for API communication
- **DeviceFactory**: Factory for creating device instances
- **VariableManager**: Handles IP-Symcon variable registration

### Best Practices Applied:

1. **SOLID Principles**: Each class has a single responsibility
2. **DRY**: Eliminated code duplication through inheritance and composition
3. **Error Handling**: Comprehensive exception handling with specific error types
4. **Type Safety**: Strict typing throughout the codebase
5. **Testability**: Dependency injection enables easy unit testing
6. **Maintainability**: Clear separation makes the code easier to maintain and extend

### Development Guidelines:

- Always use strict typing (`declare(strict_types=1)`)
- Follow PSR-12 coding standards
- Use dependency injection instead of direct instantiation
- Write comprehensive tests for new features
- Use meaningful exception messages
- Document public APIs with PHPDoc
- Validate inputs and handle edge cases

### Testing:

Run tests with: `composer test`
Check code style: `composer cs-check`
Fix code style: `composer cs-fix`
Static analysis: `composer stan`

### Adding New Device Types:

1. Create a new device class implementing `DeviceInterface`
2. Add device-specific constants to `DeviceConstants`
3. Update `DeviceFactory` to handle the new type
4. Add device-specific variable registration if needed
